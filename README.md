# Engineering Project Foundation

A domain-neutral workspace for capturing an engineering project's context, requirements, decisions, designs, verification evidence, and delivery constraints.

## Start Here

1. Complete [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) with the project purpose, stakeholders, scope, and lifecycle stage.
2. Record measurable needs in [REQUIREMENTS.md](REQUIREMENTS.md), then maintain detailed requirement records in `requirements/` as needed.
3. Document constraints, boundaries, and major interfaces in [ARCHITECTURE.md](ARCHITECTURE.md).
4. Track uncertainty in [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) and project risks in [RISKS.md](RISKS.md).
5. Capture evidence and citations in [SOURCES.md](SOURCES.md).
6. Use the templates in `templates/` for repeatable records.

## Repository Map

- `decisions/`: approved and superseded decision records.
- `research/`: investigations, experiments, and external research.
- `requirements/`: detailed requirement records and traceability data.
- `design/`: discipline-specific and system-level design artifacts.
- `verification/`: verification plans, procedures, and results.
- `manufacturing/`, `sourcing/`, `bom/`: production readiness, procurement, and parts data.
- `regulatory/`, `legal/`: compliance evidence, obligations, and legal constraints.
- `meetings/`: agendas, notes, and actions.
- `.claude/`: optional project-local Claude agent and rule configuration.

## Working Agreements

- Give records stable identifiers where practical, and link related requirements, decisions, designs, and tests.
- Distinguish verified facts from assumptions, estimates, and unresolved questions.
- Record source, owner, status, and date on consequential project artifacts.
- Keep controlled or sensitive data out of version control unless repository access and handling have been approved.
- Update summaries when underlying project decisions materially change.
